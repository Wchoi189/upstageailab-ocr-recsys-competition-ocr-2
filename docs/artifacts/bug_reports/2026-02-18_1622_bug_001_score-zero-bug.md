# Bug Report - Checkpoint Score 0.0 and Accuracy Drop on Resume Bug

**Bug ID:** BUG-001
**Related Guide:** [Checkpoint & Logging Fixes](../../guides/checkpoint_and_logging_fixes.md)

## Summary

Checkpoints were being saved with score 0.0 (e.g., `best-v3.ckpt`), and resuming training showed artificial accuracy drops (e.g., 83% → 77%). Root cause was three bugs in the recognition module's metric handling.

## Environment

- **Framework:** PyTorch Lightning
- **Module:** `ocr/domains/recognition/module.py`
- **Metric:** `CharErrorRate` (`rec_cer`)

## Symptoms

1. **Checkpoints saved with score 0.0** (e.g., `best-v3.ckpt`)
2. **Accuracy drop on resume**: Training reports 83% but resume shows 77%
3. **Inconsistent metric values** between epochs

## Root Cause Analysis

### Bug #1: Metric Never Reset (CRITICAL)

**Location:** `ocr/domains/recognition/module.py`

**Problem:** The `CharErrorRate` metric (`rec_cer`) was never reset between validation epochs.

```python
# BEFORE (buggy)
def on_validation_epoch_start(self):
    if self._high_loss_audit_enabled():
        self._clear_high_loss_epoch_buffer()
    # BUG: Missing self.rec_cer.reset()

def on_validation_epoch_end(self):
    self._log_high_loss_audit()
    # BUG: Missing self.rec_cer.reset()
```

**Impact:**
- Metric state accumulates across ALL epochs
- Checkpoint at epoch 0 has 0.0 because metric hasn't been properly computed
- On resume, loaded metric state is stale, causing incorrect initial values
- Accuracy appears lower on resume because metric is averaging old + new data

### Bug #2: Missing `on_epoch=True` Flag

**Location:** `ocr/domains/recognition/module.py:_compute_metrics`

**Problem:** Metrics logged without `on_epoch=True` flag.

```python
# BEFORE (buggy)
self.log("val/acc", batch_acc, batch_size=len(pred_texts), prog_bar=True)
self.log("val/cer", self.rec_cer, batch_size=len(pred_texts), prog_bar=True)

# AFTER (fixed)
self.log("val/acc", batch_acc, batch_size=len(pred_texts), prog_bar=True, on_epoch=True, sync_dist=True)
self.log("val/cer", self.rec_cer, batch_size=len(pred_texts), prog_bar=True, on_epoch=True, sync_dist=True)
```

**Impact:**
- Lightning doesn't properly aggregate batch metrics into epoch metrics
- Checkpoint callback reads incorrect/incomplete metric values
- Can result in 0.0 if metric isn't aggregated by epoch end

### Bug #3: Missing `_checkpoint_metrics`

**Location:** `ocr/domains/recognition/module.py:on_validation_epoch_end`

**Problem:** Recognition module doesn't set `_checkpoint_metrics` like detection module does.

```python
# AFTER (fixed)
def on_validation_epoch_end(self):
    # Set checkpoint metrics for consistent checkpoint saving
    if hasattr(self, "trainer") and self.trainer:
        self._checkpoint_metrics = {
            "val/acc": float(self.trainer.callback_metrics.get("val/acc", 0.0)),
            "val/cer": float(self.trainer.callback_metrics.get("val/cer", 0.0)),
        }
```

**Impact:**
- CheckpointHandler has no explicit metrics to save
- Relies on implicit torchmetrics state (which was buggy due to Bug #1)

## Why Accuracy Drops on Resume

**Example:** Training shows 83%, resume shows 77%

**Explanation:**

1. **During original training:**
   - Epoch 0: `rec_cer` accumulates batch 1, batch 2, ..., batch N
   - Epoch 1: `rec_cer` continues accumulating (BUG - never reset!)
   - Epoch 10: `rec_cer` has accumulated ALL batches from epochs 0-10
   - Reported "epoch 10 accuracy" is actually average of epochs 0-10

2. **Checkpoint saved at epoch 10:**
   - Contains `rec_cer` state with accumulated data from epochs 0-10
   - `best_model_score` = 0.83 (but this is averaged over 11 epochs!)

3. **On resume at epoch 11:**
   - `rec_cer` state loaded from checkpoint (has old accumulated data)
   - First validation batch: metric computes on top of old state
   - Reported accuracy = weighted average of old + new data
   - Appears as 77% because old data dilutes new performance

4. **After fix:**
   - `rec_cer.reset()` called at epoch start
   - Fresh metric computation each epoch
   - Resume shows correct accuracy immediately

## Why Score is 0.0 at Epoch 0

**Checkpoint:** `best-v3.ckpt` (epoch=0, step=1, score=0.0)

**Sequence:**
1. Training starts
2. Epoch 0 begins
3. Validation runs (first batch)
4. `rec_cer` accumulates first batch
5. **Checkpoint saved BEFORE validation completes** (step=1)
6. `trainer.callback_metrics["val/acc"]` = 0.0 (not fully computed yet)
7. Checkpoint saves with score 0.0

**Contributing factors:**
- No metric reset → initial state is 0.0
- Early checkpoint save → metric not fully aggregated
- Missing `on_epoch=True` → Lightning doesn't know to wait for epoch end

## Fix Applied

**File:** `ocr/domains/recognition/module.py`

### Change 1: Reset metrics at epoch start
```python
def on_validation_epoch_start(self):
    """Reset metrics at start of validation epoch."""
    self.rec_cer.reset()  # ← ADDED

    if self._high_loss_audit_enabled():
        self._clear_high_loss_epoch_buffer()
```

### Change 2: Reset metrics at epoch end (defensive)
```python
def on_validation_epoch_end(self):
    self._log_high_loss_audit()

    # Set checkpoint metrics
    if hasattr(self, "trainer") and self.trainer:
        self._checkpoint_metrics = {
            "val/acc": float(self.trainer.callback_metrics.get("val/acc", 0.0)),
            "val/cer": float(self.trainer.callback_metrics.get("val/cer", 0.0)),
        }

    self.rec_cer.reset()  # ← ADDED
```

### Change 3: Add `on_epoch=True` and `sync_dist=True`
```python
def _compute_metrics(self, pred_texts, gt_texts):
    self.rec_cer(pred_texts, gt_texts)

    matches = sum([1 for p, g in zip(pred_texts, gt_texts, strict=True) if p == g])
    batch_acc = matches / len(pred_texts) if len(pred_texts) > 0 else 0.0

    # Added on_epoch=True, sync_dist=True
    self.log("val/acc", batch_acc, batch_size=len(pred_texts), prog_bar=True, on_epoch=True, sync_dist=True)
    self.log("val/cer", self.rec_cer, batch_size=len(pred_texts), prog_bar=True, on_epoch=True, sync_dist=True)
```

## Expected Behavior After Fix

### Training
- ✅ Each epoch reports independent accuracy (no accumulation)
- ✅ Epoch 0 accuracy reflects only epoch 0 data
- ✅ Checkpoint scores match reported epoch accuracy

### Resume
- ✅ Resume accuracy matches last epoch before save
- ✅ No artificial drop (83% → 77% bug fixed)
- ✅ Fresh metric computation from first validation batch

### Checkpoint Saving
- ✅ No more 0.0 scores (unless actual accuracy is 0.0)
- ✅ `best_model_score` reflects true epoch performance
- ✅ Consistent metric values in checkpoint metadata
