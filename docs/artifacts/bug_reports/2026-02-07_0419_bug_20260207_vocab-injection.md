## Description
The `OCRProjectOrchestrator` failed to inject the correct `vocab_size` (1027) into the PARSeq model configuration when `component_overrides` was not explicitly defined in the YAML config. This caused the model to default to a hardcoded vocabulary size (likely 1000) while the dataset contained token IDs up to 1022.

## Impact
- **Severity**: Critical
- **Effect**: Training crashes immediately (on GPU) or produces garbage output (on CPU) due to `index out of bounds` errors in the embedding layer.
- **Error Message**: `RuntimeError: CUDA error: device-side assert triggered` (specifically `indexSelectLargeIndex` failure).

## Reproduction Steps
1. Configure an experiment using `PARSeq` model and a dataset with vocabulary > 1000.
2. Do NOT provide explicit `component_overrides` in the Hydra config.
3. Run training on GPU.
4. **Outcome**: Crash during the first forward pass.

## Root Cause Analysis
The injection logic in `orchestrator.py` had two flaws:
1. **Conditional Execution**: It returned early if `component_overrides` was missing, or failed to create the structure if it didn't exist.
2. **Strict Hierarchy**: It attempted to inject into nested `params` keys (`model.component_overrides.head.params.out_channels`), but the atomic `PARSeq` configuration structure is flat (`head.out_features`), causing the injection to be ignored by the model factory or `instantiate` call.

## Resolution
Modified `ocr/pipelines/orchestrator.py` to:
1. Robustly create `component_overrides` structure if missing.
2. Inject parameters using **both** flat keys (`out_features`, `vocab_size`) and nested keys (`params...`) to support both Atomic and Legacy architectures.
3. Update specific keys for Linear heads (`out_features`) and Transformer Decoders (`vocab_size`).
4. Update the global `cfg.model.vocab_size` variable for correct interpolation.

## Verification
- Confirmed fix by running `rec_baseline_v1` experiment.
- Training stability confirmed for >300 steps.
- Logs show correct injection: `✓ Head vocab injection (size=1027)` and `✓ Decoder vocab_size = 1027`.
